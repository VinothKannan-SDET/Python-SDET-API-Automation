# LinkedIn Milestone — SDET API Automation

## Suggested headline

**SDET Milestone #2 — Built a Python API Automation Framework with BDD, CI/CD, Parallel Execution and Allure Reporting**

## Suggested post

I’m sharing my second SDET portfolio milestone: a Python-based API automation framework built to demonstrate how I approach automation as a senior engineer — not just how I write API tests.

### What I implemented

- Python + pytest + Requests
- Reusable `requests.Session` based API client
- Authentication and Booking domain clients
- Dynamic API chaining using generated booking IDs
- Positive, negative and boundary testing
- JSON Schema contract validation
- Reusable test-data factories and domain models
- pytest-bdd scenarios for business-readable API behavior
- Centralized secret-safe request/response evidence in Allure
- Parallel execution with pytest-xdist
- GitHub Actions CI/CD
- JUnit reporting + interactive Allure HTML reporting
- GitHub Pages publication for the Allure report
- Test strategy, architecture and senior-level interview documentation

The goal was not to create a large number of repetitive tests. The goal was to demonstrate maintainability, test isolation, diagnostics, security, scalability and CI/CD readiness.

This milestone is part of my continued transition toward modern Senior SDET / Quality Engineering roles, with the next portfolio milestones focusing on performance, microservices/contract testing, modern UI automation and AI testing.
