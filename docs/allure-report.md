# Allure Reporting

The framework has two reporting outputs:

1. `allure-results/` — raw Allure execution data generated by `allure-pytest`.
2. `allure-report/` / `allure-history/` — static HTML report generated in CI.

The GitHub Actions workflow:

1. Runs the regression suite in parallel.
2. Generates raw Allure results and JUnit XML.
3. Loads the previous `gh-pages` report history.
4. Generates the HTML Allure report.
5. Uploads raw results, JUnit and HTML artifacts.
6. Publishes `allure-history` to the `gh-pages` branch on pushes to `main`.

## One-time GitHub setup

In the repository, open **Settings → Pages** and set **Build and deployment → Source** to **Deploy from a branch**. Select:

- Branch: `gh-pages`
- Folder: `/ (root)`

After the first successful push workflow, GitHub Pages will expose the report at:

```text
https://<github-user>.github.io/<repository-name>/
```

The history action preserves Allure history so the report can show trends and previous executions. Allure's documentation describes copying previous report history into the next generation as the mechanism used for historical charts.
